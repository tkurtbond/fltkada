Bugs to fix:

Fl_Wizard draw() method private/protected

GNAT bug with type_invariant combined with derived type and a begin section in a package, eg dialogs.adb

Fl_Bitmap / Fl_XBM_Image instances will always have fail() return ERR_NO_IMAGE

Fl_Positioner has poor docs for value/xvalue/yvalue set methods

code for Fl_Menu_Item::test_shortcut seems to use FL_SUBMENU to assume userdata
points to another menu item array, not FL_SUBMENU_POINTER, is this still in
the latest version?

Fl_Table::callback has wrong signature, still around and unfixed in 1.4
possibly this hasn't been noticed because it's only visible to doxygen

Menu.Add (Text) with one argument is ambiguous between the defaulted Add
overloads; callers must write Add (Text, null)

calling Remove_Clipboard_Notify from inside a clipboard notify handler raises
Program_Error (the handler vector is tamper-checked while it is being iterated);
the other Events handler vectors likely have the same problem

Dispatch_Hook's Constraint_Error handler reports any Constraint_Error raised in
the user's dispatch function as an unexpected event value; several other hooks'
handlers relabel the user's Constraint_Error or Assertion_Error the same way
(FLTKAda-BUGS.md 45)

Events.Get_Grab can't return a window FLTK made itself, such as a pop-up
menu's: it gives null, or Internal_FLTK_Error under -gnata (FLTKAda-BUGS.md 44)

Menu_Item Set_Label (Kind => Image_Label or Multi_Label, Text) is meaningless,
since FLTK treats the label text as a pointer to an image or Fl_Multi_Label;
use Set_Image / Set_Multi_Label instead

FLTK's glut.H declares glutExtensionSupported as taking char*, but its
definition takes const char* (see body/c_fl_glut.cpp)



Bugs fixed while porting FLTK's examples/:

Fl_Text_Editor: every key binding with Shift/Ctrl/Alt/Meta was dead, because
all keys were routed via default_key_function_, which FLTK only calls with no
modifiers; and Key_Func_Hook masked in NumLock/CapsLock

Widget Extra_Init set an empty label as "" rather than NULL, so unlabelled
widgets (including wrapped C++-owned ones such as Table's scrollbars and the
fl_message_icon template) drew a label: Table's Start_Page font was reset,
images on unlabelled boxes were offset, and ask/message dialogs lost their icon

Window Forge.Create (Parent, X, Y, W, H, ...) made an invisible subwindow;
it is now shown, as a C++ Fl_Window(x,y,w,h) inside a current group is

handle() results were converted with Event_Outcome'Val, raising
Internal_FLTK_Error when FLTK returned a nonzero value other than 1

FLTK.Static registered its clipboard notify hook at elaboration, before the
display was open, so on X11 every program polled the clipboard twice a
second forever; the hook is now registered with the first Ada handler

Menu_Item labels pointed at Ada temporaries (dangling, and freed by
Fl_Menu_::clear); the shim now copies text labels and frees them

Text_Displays Style_Entry had the wrong layout (Hue at byte 4, 16 bytes not
20); it now matches Fl_Text_Display::Style_Table_Entry, with attr and bgcolor

Table Callback_Row/Callback_Column/Get_Selection raised on FLTK's -1 (none)
values; they are now Natural, with 0 meaning none

Table let the widgets in its cells be deleted by ~Fl_Group and then freed
by Ada; Remove (Place) reached its scrollbars; Find of a widget not there
gave an index past the end (FLTKAda-BUGS.md 39)

Text_Buffer left its modify and predelete hooks in a C++ buffer a display
still held, which called them with the freed record (FLTKAda-BUGS.md 40)

Textline_Browser kept only a pointer to an icon's image, which could go
first, and kept icons by line number, so they didn't follow their lines
(FLTKAda-BUGS.md 42)

An exception raised in any hook FLTK calls unwound through FLTK's C++ and
left it broken; hooks now save it and the binding re-raises it when control
is back in Ada, from Wait, Check, Run, the dialogs, menus and Do_Callback
(FLTK.Hook_Exceptions; FLTKAda-BUGS.md 43)

Menu_Item.Forge.Create left the item's label type, font, size and colour
uninitialised (FLTKAda-BUGS.md 46)

Calls made before the display was open, or with no window shown, crashed
FLTK: the clipboard and selection, Ready, system input, a key or DND_LEAVE,
and the font calls; the shim now opens the display first, as
FLTK.Static.Open_Display does (PLAN.md Phase 3)

Overlays, Scroll, Make_Current, GL text and Start, and Set_Grab crashed
without the window or context they need; they now raise Program_Error, or
Unsupported_Error for GL Start on Wayland, and a freed widget no longer
stays the grab or the selection owner (PLAN.md Phase 3)

A menu popped up straight after its window's Show killed the program on
Wayland; Popup and Pulldown now wait for that window (PLAN.md Phase 3)

FLTK.Tree_Items / FLTK.Widgets.Groups.Trees -- deliberately scoped to the
common ~60% of the Fl_Tree / Fl_Tree_Item API rather than full parity
(see doc/binding_architecture.md for the design notes). Not bound:
  - standalone/detached Fl_Tree_Item construction (new_fl_tree_item);
    items are only ever obtained from a Tree.
  - the raw move(int,int)/move(item,op,pos) and replace_child() are NOT
    bound, but the higher-level operations built on them ARE:
    Trees.Insert/Insert_Above (parallel to Add, for a specific position
    rather than appending) and Tree_Items.Move_Above/Move_Below/
    Move_Into/Deparent/Reparent/Swap_Children (item restructuring).
    replace() IS bound (Tree_Items.Replace), as is add(path, newitem)
    (Trees.Add with an Item), so custom items can be put in the tree.
  - Fl_Tree_Item's labelfont/labelsize ARE bound (Tree_Items.Get/
    Set_Label_Font, Get/Set_Label_Size), along with label_x/y/w/h;
    labelfgcolor/labelbgcolor are not.
  - widget() embedding IS bound (Tree_Items.Set_Widget/Has_Widget/
    Get_Widget), along with item_draw_mode() (Tree_Items.Item_Draw_Mode,
    Trees.Get/Set_Item_Draw_Mode) and widgetmarginleft()
    (Trees.Get/Set_Widget_Margin_Left) -- both needed to make an
    embedded widget lay out sensibly, following the same
    FL_TREE_ITEM_DRAW_LABEL_AND_WIDGET | FL_TREE_ITEM_HEIGHT_FROM_WIDGET
    pattern as FLTK's own examples/tree-of-tables.cxx. test/tree.adb
    embeds a live FLTK.Widgets.Groups.Tables.Table this way.
  - per-item icons (usericon/userdeicon) ARE bound
    (Tree_Items.Set/Has/Clear/Get_User_Icon and the _Deicon equivalents).
    Get_User_Icon/Get_User_Deicon can't recover the Ada object the way
    Get_Widget does (Fl_Image has no spare pointer to piggyback on like
    Fl_Widget's user_data()), so they're backed by a small internal
    table in FLTK.Tree_Items keyed by the *item's* address -- stale if
    that address is later reused for an unrelated item, same caveat
    FLTK.Registry's Label_Store already carries. The tree-wide default
    icons (Fl_Tree::usericon/openicon/closeicon, as opposed to a
    specific item's) are still not bound.
  - overriding draw_item_content() IS bound, through the separate
    FLTK.Tree_Items.Custom package: derive from Custom_Item and override
    Draw_Item_Content (see examples/tree_custom_draw_items.adb).
  - callback_item()/callback_reason() ARE bound (Trees.Callback_Item,
    Callback_Reason, Reason_Kind), as are item_pathname(), selectbox()
    (Trees.Get/Set_Select_Box) and show_self(). item_draw_callback() is not.
  - the path-string overloads of open/close/select/is_open/is_selected,
    and their docallback parameter (Tree-level Open/Close/Select_Item/
    Deselect always behave as if docallback=1).
  - Fl_Tree_Prefs as a standalone bindable object -- its settings are
    exposed only via Fl_Tree's own forwarding methods, matching what
    FLTK's own docs recommend using instead of Fl_Tree_Prefs directly.
  - scrollbar/position controls (vposition/hposition/scrollbar_size),
    load() from Fl_Preferences.
See test/tree.adb and the examples/tree_*.adb ports for working examples
of what is bound.
