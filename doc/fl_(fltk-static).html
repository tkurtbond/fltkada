Package name
Fl FLTK.Static

Note:

FLTKAda never calls fl_open_display by itself at elaboration, so a program that only uses FLTK.Filenames or FLTK.Environment needs no display. Showing the first window opens the display, and so do the calls FLTK 1.4.5 would crash in with no display open, which call fl_open_display themselves: Ready, Copy, Paste, Selection, Clipboard_Contains, Enable_System_Input, Disable_System_Input, Set_Box_Color, Widget.Take_Focus, Events.Set_Focus, GL_Window.Can_Do, GLUT.Get and Copy_Surface's Forge.Create. A program may still call Open_Display first, to choose when the connection is made, and so when FLTK stops the program if there is no display ("Can't open display" on X11, "No Wayland connection" on Wayland). Calling it again does nothing.
